# ff14-macro-helper Architecture

## 構成

MVP はサーバーレスの静的 Web アプリである。編集・解析・補完・lint・ログ変換をブラウザ内で完結させる。

- **UI 層**: エディタ、補完メニュー、診断一覧、チップヘルプ、ログ、コピー／共有操作
- **編集状態層**: 本文、カーソル位置、選択中候補、URL 復元状態などの一時的な UI 状態
- **ドメイン層**: マクロ分割、トークン化、コマンド照合、診断、補完候補、ログ変換
- **辞書層**: `CommandDefinition` と、その出典・確認状態
- **入出力層**: URL のエンコード／デコード、クリップボード、必要最小限の端末内下書き保存

## 推奨ディレクトリ

```text
src/
  app/                 # ページ構成とルーティング
  components/          # エディタ、候補、診断、ログなどの表示部品
  hooks/               # キーボード、クリップボード、URL 同期などの UI 補助
  lib/
    macro/             # 解析、正規化、lint、補完、ログ変換
    commands/          # 辞書、辞書の読込、検索
    share/             # URL 形式、エンコード、デコード
  data/commands/       # レビュー済みの公式由来コマンドデータ
  styles/              # デザイントークンとグローバル最小スタイル
```

## データフロー

1. ユーザーの本文、または URL の共有データを受け取る。
2. `MacroDocument` を検証し、本文を行とトークンに分ける。
3. コマンド辞書を使って別名を正規化し、構文情報を付加する。
4. ドメイン層で行数・行長・構文・コマンド固有のルールを診断へ変換する。
5. 同じ解析結果から補完候補、チップヘルプ、構文ハイライト、ログプレビュー用モデルを作る。
6. UI はそれらのモデルを表示する。UI は制約やコマンドの意味を判断しない。
7. コピーは元の本文を使い、共有はバージョン付き文書を URL 用にエンコードする。

```text
本文 / 共有 URL
      ↓
URL 検証・入力正規化
      ↓
解析（行・トークン・別名） ← コマンド辞書
      ↓
診断 / 補完 / ヘルプ / ログ変換
      ↓
エディタ・診断一覧・ログ・コピー／共有 UI
```

## 責務分離

### エディタとドメインロジック

エディタは本文・選択範囲・カーソル位置を保持するだけにする。文字数、行数、コマンドの存在、引数の正しさをエディタ部品が直接判定してはならない。解析 API の出力を使い、同じ内容が URL 復元・テスト・将来の GUI 組み立てでも同じ診断になるようにする。

### コマンド辞書

辞書は UI 文言ではなくドメインデータである。正式名、短縮名、構文、説明、カテゴリ、出典、確認日、サポートレベルを同じレコードで保持する。AI による要約と公式原文を混同せず、公式 URL を必ず残す。

### ログプレビュー

ログ変換はゲームのシミュレータではない。対応する行を表示形式へ変換する pure function とし、対象・ジョブ・戦闘状態が必要なコマンドには「再現できない」行を返す。エラーは診断から生成し、UI で独自に赤表示の条件を判断しない。

## 保存・共有方針

- **共有の正本**: URL に埋め込んだ `MacroDocument`。
- **下書き**: 必要になった時だけブラウザ内保存を使う。共有 URL を上書きする永続的な正本にはしない。
- **MVP のサーバー／DB**: 不要。
- **将来の永続データ**: 短縮 URL、公開マクロ、アカウント保存に DB が必要になった場合は Neon を使う。Upabase は新規採用しない。

## 例外方針

- 不正な共有 URL は、復元を試みずエラーと安全な空の編集状態を表示する。
- 辞書にないコマンドは本文を保持したまま警告する。勝手な書き換えはしない。
- 辞書にはあるが未対応のコマンドは、参照情報を表示し、lint／ログの限界を明示する。
- 公式情報と実機の差異を発見した場合は、辞書に暫定状態を記録し、個別に確認してから修正する。
