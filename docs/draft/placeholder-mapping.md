# プレースホルダ代入ルール（下書き）

出典: https://jp.finalfantasyxiv.com/lodestone/playguide/db/text_command/placeholder/
（Patch 7.56、2026-09-09 確認）

## メモ

- `<wait.(秒数)>` は最大60秒（超過は60扱い）という上限規定あり。既存の `/wait` コマンド側の lint に未反映の可能性、確認要。
  - → 必要
- 挙動のパターンは大きく3種類ありそう。記入欄にはこの区分で書くと実装の分岐にそのまま落とし込みやすい。
  - 値に置換して表示される（`<t>` `<hp>` 等）
    - 上記文字列そのままでOK
    - <>とするか他の文字にするか相談
  - 非表示（実行制御のみ、`<wait.s>` 等）
    - waitのみ非表示。Playボタン実装時にシミュレート
  - 音のみで文字は出ない（`<se.x>`）
    - → 指示ミス。表示されてよい。

## 代入時の表記ルール（決定）

- 実際の値に置き換わる系（`<YourPetName>` のような読みやすいラベル）は半角アスタリスク2個で挟む: `**YourHP%**`
  - 理由: `<>` は実際にマクロへ入力する記法と紛らわしい、`【】` はチャット文中の強調でよく使われ紛らわしい、`{}` はエンジニア以外に馴染みが薄い
  - `**` は全角日本語の中で半角記号が浮く「狙った違和感」を利用（Strataの文体ルールにある全角/半角のリズムと同じ発想）
  - Markdown記法と衝突しない（アプリ内はプレーンテキスト表示のため）が、Strata等Markdownレンダラを通す場所へコピペする際は太字化する点に注意
- 元の記法をそのまま出す系（`<8>` `<se.1>`〜`<se.16>` など、読みやすい名前をつけようがないもの）は `<>` のまま
- 表示方法は将来的に背景色つきバッジ（チップ）化する方向で合意。実装には `LogEntry.text` を文字列からセグメント配列に変える必要あり（エディタ側ハイライトと同じ構造）。色をエディタの `arg-placeholder`（紫系）に揃える。
- `<tt>` はフルスペル展開（TargetOfTargetName 等）だと長すぎるため `**ttName**` に短縮。
- `<recast.(アクション名)>` は数値であることが分かりにくいので `**CDsec**` に決定（GCD等、クールダウンを CD と略す慣例に合わせた）。

## 実機確認済み（2026-09-09、渚さん確認）

- `<wait.(秒数)>` を行の途中に置いた場合、エラーにはならない。「指定秒数待機した上で、`<wait.x>` より後ろの文字列を無視する」という挙動。
  - 例: `/party ここまで表示<wait.3>ここは消える` → 実際に送信されるのは「ここまで表示」のみ、3秒待機してから次の行へ進む
  - ログプレビュー実装への影響: `argsText` 中に `<wait.\d+>` が現れたら、
    1. そこより前の部分だけを送信テキストとして表示する
    2. 該当秒数を経過時間（疑似タイムスタンプ）の累積に加算する
    3. `<wait.x>` 自体と、それより後ろの文字列は完全に破棄する（非表示ではなく「そもそも送信されない」）
  - 上記により「行末以外だとエラー」という当初の想定は誤りだったことが判明。lint のエラー対象には含めない。
